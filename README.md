# Budget Dictionaries API

Python backend для бюджетных справочников и правил подбора МРП по ЦФО и бюджетной статье. Пример показывает реализацию функциональности через доменные модели, пользовательские сценарии, асинхронные репозитории и HTTP API.

## Реализованная функциональность

- Создание и переименование категорий и статей, нормализация пробелов и регистра для проверки уникальности названий.
- Архивирование и восстановление записей, выдача активных записей по умолчанию.
- Архивирование категории вместе с её активными статьями в одной транзакции.
- Перенос статьи между категориями и проверки состояния связанной категории при создании, переносе и восстановлении.
- Управление справочниками ЦФО, МРП и организаций: создание, переименование, архивирование и восстановление.
- Основное и внешнее наименования организации, нормализация пробелов, регистра и вариантов кавычек во внешнем наименовании, отдельные проверки уникальности обоих имён.
- Создание, изменение, удаление и просмотр правил соответствия «ЦФО + бюджетная статья → МРП». Пара ЦФО и статьи уникальна; новые связи требуют активных записей. Неизменённые ссылки на архивные записи разрешены при редактировании существующего правила.
- Подбор МРП по правилу: отсутствие правила или отсутствующая/архивная связанная запись дают отсутствие рекомендации. Это не алгоритм расчёта или распределения денежных сумм.
- Список правил с данными связанных справочников, включая категорию бюджетной статьи.
- ORM-модели и миграции Alembic: уникальные нормализованные названия, внешние ключи, ограничение удаления связанных записей и уникальность пары в правиле.
- Структурированные ошибки с кодом и контекстом, HTTP-ответы для ошибок валидации, конфликтов и отсутствующих записей.

## Слои

```text
backend/sigma/
  main.py                         сборка приложения
  shared/                         БД, настройки и логирование
  modules/dictionaries/
    domain.py                     сущности и бизнес-правила без зависимости от ORM
    features/                     отдельные пользовательские сценарии
    repository.py                 интерфейсы Protocol и SQLAlchemy-реализации
    models.py                     ORM-модели
    facade.py                     публичный интерфейс модуля и границы транзакций
    presentation/                 FastAPI-эндпоинты и схемы
    routes.py                     подключение роутеров и обработчиков ошибок
```

HTTP-слой обращается к функциональности модуля через фасад. Сценарии используют интерфейсы репозиториев; доменные сущности не зависят от HTTP или SQLAlchemy. Границы импортов проверяются import-linter.

Стек: Python 3.14, FastAPI, Pydantic, SQLAlchemy async, PostgreSQL/asyncpg, Alembic, structlog, pytest. Инструменты проверки: Ruff, basedpyright, import-linter, complexipy.

## Статус и границы примера

Исходный проект находится в разработке. В этом репозитории представлен полный срез backend-модуля `dictionaries`: категории, статьи, ЦФО, МРП, организации и правила распределения. Заявки, модуль доступа, фронтенд и остальные подсистемы не включены. Рабочие данные и заполненные справочники не переносятся.

Авторизация и проверка прав в демонстрируемом срезе не реализованы. Зависимость проверки администратора — точка подключения будущей авторизации, а не готовая защита доступа. Пример предназначен для локального изучения реализации через слои, не для открытого развёртывания с рабочими данными.

Основной набор из 611 тестов проверяет доменные правила, сценарии, преобразования ORM, транзакционный фасад и HTTP-контракты с моками репозиториев/сессии. Ещё 6 интеграционных сценариев запускаются отдельно с PostgreSQL: миграции и соответствие ORM, ограничения уникальности и внешних ключей, HTTP → БД для правил и организаций. Это не полный набор проверок конкурентного доступа, нагрузки или production-окружения.

## Локальный запуск

Нужны Python 3.14, uv и отдельная локальная БД PostgreSQL. Из корня репозитория:

```powershell
cd backend
uv sync --frozen
$env:DATABASE_URL = "postgresql+asyncpg://postgres:postgres@localhost:5432/budget_dictionaries"
uv run alembic upgrade head
uv run uvicorn sigma.main:app --host 127.0.0.1 --port 8000
```

Базу `budget_dictionaries` нужно создать заранее; учётные данные в примере замените на параметры своего локального окружения. Настройки также можно задать в `backend/.env`, который исключён из Git.

Документация API: `http://127.0.0.1:8000/docs`. Основные маршруты: `/dictionaries/categories`, `/dictionaries/articles`, `/dictionaries/cfos`, `/dictionaries/mrps`, `/dictionaries/organizations`, `/dictionaries/savings-distribution-rules`; проверка доступности: `/health`.

### Интеграционные проверки PostgreSQL

Нужна отдельная пустая БД с именем, начинающимся на `sigma_test_`. Нельзя указывать рабочую БД: тесты создают и удаляют таблицы. Непустая БД отклоняется; пустая служебная таблица Alembic после предыдущего прогона допустима. Пример для локального PostgreSQL, из `backend/`:

```powershell
createdb -h 127.0.0.1 -U postgres sigma_test_dictionaries
$env:SIGMA_TEST_DATABASE_URL = "postgresql+asyncpg://postgres:postgres@127.0.0.1:5432/sigma_test_dictionaries"
uv run --frozen pytest -q -m postgres
# Или весь набор: 617 тестов при доступной тестовой БД.
uv run --frozen pytest -q
```

Параметры подключения замените на свои. Тесты сначала создают старую схему категорий и статей, добавляют синтетическую запись, обновляют схему до текущей и проверяют сохранность данных. После сценариев выполняется откат до старой схемы и до `base`, затем повторный полный upgrade/downgrade. Каждый сценарий работает в откатываемой транзакции; HTTP-запросы используют настоящие репозитории и отдельные сессии, но подключение к БД подменяется на тестовое. HTTP-сервер и внешние сервисы не запускаются.

В самостоятельной цепочке единственная текущая ревизия — `f1a8d725c630`. Базовая ревизия `a5cfcb331828` сохранена, поэтому локальную БД первой версии примера можно обновить командой `alembic upgrade head`. Миграции закрытого приложения, связывающие справочники с модулем доступа, к этой цепочке не относятся.
